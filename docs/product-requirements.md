# OpenLLMOps 产品需求基线（MVP）

## 1. 用户与部署范围

- 系统服务于内网单管理员，不实现多租户、组织和复杂 RBAC。
- 管理入口支持 HTTPS 登录；OpenAI 兼容接口通过 API Key 访问。
- 控制面使用 Docker Compose 单机部署；推理、训练和测评容器由受限 Node Agent 动态创建。
- 生产环境为 4 × RTX 4090D，无 NVLink；开发环境可使用 2 卡，所有 GPU 均按整卡独占分配。

## 2. 模型资产

### 2.1 来源

- Hugging Face 在线拉取：仓库 ID、revision、可选访问令牌。
- ModelScope 在线拉取：模型 ID、revision、可选访问令牌。
- SFTP/人工拷贝：管理员在系统外把目录放入受控入口，界面扫描后选择导入。

### 2.2 校验与管理

- 展示传输字节数、速率、阶段、错误原因，并支持取消未完成导入。
- 只接受 Safetensors，检查模型配置、Tokenizer、权重索引和文件完整性。
- 记录来源、revision/commit、文件清单、总大小、SHA-256、架构、参数精度和创建时间。
- 支持列表、筛选、详情、软删除；被部署或任务引用的版本不得删除实体文件。
- 资产类别至少区分生成模型与 Embedding 模型；训练产物通过来源和 manifest 标识 Adapter、
  checkpoint 或已合并模型，只有具备完整模型目录的产物可直接部署。

## 3. 推理部署

### 3.1 创建配置

- 简化模式：名称、模型版本、部署类型、指定 GPU、张量并行度、精度、最大上下文、显存利用率与 API 模型名。
- 高级模式：在白名单内映射 vLLM 参数，实时显示生成的结构化参数与风险提示；禁止任意 shell 和 `trust_remote_code`。
- 创建前校验 GPU 编号/数量、张量并行度和 API 模型名；实际显存能否容纳模型仍由节点启动
  门禁与 vLLM 健康检查确认，首版不承诺仅凭参数量给出可靠显存估算。

### 3.2 生命周期

- 列表展示期望状态、实际状态、GPU、端点、启动时间、健康检查和最近错误。
- 支持启动、停止、编辑、详情和删除。操作幂等，执行过程可追踪。
- 控制面重启后自动恢复期望为运行的推理服务；启动失败不得无限重试。
- 生成模型对外提供 `/v1/completions` 和 `/v1/chat/completions`；Embedding 模型提供 `/v1/embeddings`。

## 4. 数据集

- 支持 CPT、SFT 与 Evaluation 三类 JSONL 上传。
- 上传采用流式写盘并计算 SHA-256，限制文件大小、行长、JSON 深度和错误行比例。
- CPT 至少支持 `text`；SFT 支持 Alpaca 与 messages 两种规范化格式；评测支持选择题、分类和短问答。
- 展示版本、大小、行数、字段、校验结果与抽样预览；预览内容必须转义。
- 数据集一旦被任务引用即不可覆盖，只能创建新版本。

## 5. 训练

- 继续预训练（CPT）仅支持 LoRA。
- 监督微调（SFT）支持 Freeze、LoRA 和 QLoRA。
- 简化表单覆盖常用超参数；高级配置展示最终 LLaMA-Factory 配置并对字段做白名单校验。
- 提交后按 FIFO 非抢占排队。GPU 不足时提示管理员手工停止推理；系统不得自动抢占。
- 通过周期状态上报监控 epoch、step、loss、learning rate、吞吐、ETA、GPU 利用率与显存；原始容器日志不作为首版管理 API 合同。
- 支持终止任务，并导出通过安全复核的 checkpoint、adapter 与合并模型。首版不支持从 checkpoint 恢复优化器状态；需要续训时，以原基础模型、不可变数据集和参数创建新任务。
- 训练完成后可登记合并模型版本并进入部署流程。

## 6. 测评

- 内置 C-Eval 与 CMMLU 中文通用能力数据集，并记录其许可与版本。
- 自定义领域数据集接受 JSONL 选择题、分类和短问答。
- Base 模型与 Instruct 模型使用各自模板，评测运行必须固定模板、随机种子与生成参数。
- 结果至少包括样本数、正确数、正确率、分类/主题明细、无效输出数和耗时。
- 前后对比显示基线与候选百分比、百分点变化、相对变化；通用集用于观察灾难性遗忘，领域集用于观察能力提升。
- 不设置自动通过/不通过阈值，但需显式标注样本不一致或统计不可比的运行。

## 7. Playground

- 可选择运行中的生成部署，维护多轮消息并调整 temperature、top_p、max_tokens 等参数。
- 使用 SSE/兼容流实时展示生成文本，支持停止生成、复制回复、查看延迟和 token 使用量。
- 不把浏览器中的管理员登录凭证暴露给推理容器；请求统一经过 Gateway。

## 8. 资源监控

- 总览每张 GPU 的利用率、显存、温度、功耗、绑定工作负载和遥测健康状态。
- 提供 Prometheus 历史曲线；DCGM 不支持的消费卡指标显示“不可用”，不能伪造为 0。
- 资源页同时展示调度租约，并根据 DCGM 活动区分“空闲、控制面已分配、未纳管占用、
  遥测未知”；Node Agent 在启动前使用 NVML 进程检查做最终门禁。

## 9. 设置与审计

- 管理 API Key；模型仓库令牌由管理员以宿主机只读文件配置，不通过管理 API 回显或修改。
- HTTPS、受控目录、镜像白名单和保留策略属于单机部署配置，由管理员修改 `.env` 后通过
  预检并重启控制面，首版不在页面内写宿主配置。
- 审计记录操作者、来源 IP、对象、动作、结果、时间和请求 ID。

## 10. 非功能验收

- 所有写操作具有请求 ID；启动、停止、终止等状态动作具备等价幂等保护。数据集上传和
  模型导入每次请求都会创建新的不可变记录，客户端重试前必须先查询列表确认结果。
- 状态机非法转换返回冲突，不静默修改状态。
- 控制面组件有健康检查，动态容器有启动/存活探针和有界重试。
- 重要配置、状态机与安全校验具有自动化测试；前端可完成生产构建。
- `.env.example` 不含真实密钥，日志不输出 Token、密码或完整 API Key。
- 生产部署文档包含安装、TLS、初始化、备份、升级、恢复与停止步骤。
