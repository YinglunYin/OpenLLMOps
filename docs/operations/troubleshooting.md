# 故障定位

## GPU 显示空闲但任务仍排队

同时检查数据库租约、Node Agent 管理容器和 NVML 进程。系统故意把“租约过期但 Agent 失联”的 GPU 隔离，而不是立即重分配，以避免双重占卡。先恢复 Agent 通信并完成对账，不能直接删租约行。

## 多卡 vLLM 启动失败

- 确认模型在单卡无法容纳时才启用多卡，并让 `tensor_parallel_size` 等于 GPU 数量。
- 检查 PCIe 拓扑、NCCL 日志、共享内存与容器 GPU 可见性。
- 4090D 无 NVLink；不要照搬 NVLink 服务器的 P2P 假设。
- 修改 NCCL 环境变量属于部署配置变更，应在开发机复现并记录，不能在 UI 高级参数中接受任意环境变量。

## 模型导入失败

- 确认暂存区和模型仓库在同一文件系统且剩余空间包含安全余量。
- 检查 `config.json`、Safetensors 分片与索引；`.bin/.pt/.pkl` 会被主动拒绝。
- 声明 `auto_map` 或需要 `trust_remote_code` 的模型不在首版支持范围。
- 人工/SFTP 拷贝必须先落入受控 inbox，软链接和越界路径会被拒绝。

## 训练没有自动恢复

这是预期行为。控制面异常后不会盲目重启训练，以免重复覆盖 checkpoint。检查最后一个 checkpoint、数据集与配置版本，再由界面创建恢复尝试。

## DCGM 指标缺失

RTX 消费卡并不保证支持全部 DCGM 指标。先确认 exporter 能发现设备，再检查具体字段是否受支持。缺失值应在 UI 显示“不可用”；只有 exporter 明确报告 0 时才显示 0。
